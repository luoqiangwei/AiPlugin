# 安全推导与漏洞处置

先证明输入或调用能力如何越过边界，再判断后果。下面的过程已从安全验证标准、语言规则和漏洞根因提炼；无需先查完整标准。专项资料处理各平台机制，来源只用于版本核验和争议溯源。

## 结论准入：一条完整的边界穿越路径

对候选问题填出：`主体能力 → 可控制输入 → 经过的变换 → 敏感操作 → 当前控制 → 违反的授权/完整性/资源承诺`。返回拒绝码但已经写入数据仍是失败；没有前端按钮不阻止直接调用；内部字段名不证明值由可信内部组件产生。

审查要同时追两种流：**数据流**是字节、对象、路径如何进入解析/写入；**能力流**是 UID、token、FD、URI grant、管理员身份如何授予操作。先清理了数据，却把高权限能力一起转交，也可能构成漏洞。

确认一个保护有效，需要它约束所有相关入口、作用于真正操作的对象、在使用时仍成立。若缺少关键部署、权限或 API 语义，把具体缺口列为待确认；不要把“看到危险 API”写成确定利用。

## 身份、对象与操作授权

1. 主体从受验证的会话/操作系统入口取得，不能从请求里的 `userId`、`tenantId`、包名或“内部调用”标志直接相信。
2. 沿实际读写路径追对象和动作：登录、角色、列表可见、对象写权限不是同一件事；批量入口也不能因第一个对象合法就放行全体。
3. 检查权限检查到使用之间是否切换身份、换对象、离开事务或接受可变输入；查缓存、后台任务和回调是否绕过原本的授权。
4. 对委托能力问：谁能拿到、可作用于哪个对象、哪些操作、多久有效、是否可转授和撤销。

```text
风险：authorize(request.userId); update(request.documentId, request.fields)
     // 检查的是输入声称的身份，且没有绑定对象与操作
修复：subject = verifiedCaller()
      document = loadWithinAuthorizedScope(subject, documentId, UPDATE)
      applyAllowedChanges(document, parsedInput)
```

**反证**：服务、数据库行策略或可靠入口已完成所有对象/动作约束，且没有绕过路径；不要求每层复制一份同样校验。**验证**：只改变主体/对象/租户/动作中的一项，合法场景仍通过，越界场景在任何副作用前拒绝；撤销、缓存和异步路径按实际需求测试。弱点分类按根因选择 CWE-862/863/639。

## 最终解释器与注入防护

1. 找执行点，再追来源和变换，而不是看到拼接就判注入。数据库返回、缓存和第三方响应可能仍含不可信内容。
2. 区分“数据参数”与“语法元素”。参数化通常保护数据值，不表示任意表名、排序字段、模板或程序名都能安全放进参数。
3. 每次解码、拼接、嵌入另一语言后重新确定上下文；HTML 编码不能替代 JavaScript/URL 策略，shell 引号规则也不能跨平台照搬。

```text
风险：query("... ORDER BY " + request.sort)
无效思路：把任意 sort 当作 ORDER BY 的值参数，误以为可参数化列名
有效形状：order = {"recent": "created_at DESC", "name": "name ASC"}[request.sort]
          若未命中则拒绝；仅把固定映射结果放入语法位置，数据值仍正常绑定
```

**反证**：输入只是当前上下文的正确参数，或拼接来源为封闭固定集合；不用危险函数名代替可达性。**验证**：用无害元字符检查语法/查询结构与返回范围不被扩展，同时合法排序和数据保持原义。URL/DOM 细节见 Web；SpEL/JPQL 见 Spring。SQL/命令/代码的根因分别考虑 CWE-89/78/94。

## 文件路径与实际操作对象

**进入条件**：路径、归档文件名、上传落地、下载、临时文件和 URI 可被外部影响。

先列全部解析/解码/归一化步骤，确认根目录约束在最终表示上成立。接着把“校验字符串”和“打开文件”分开：它们之间目录或符号链接是否能被替换？规范化路径不能单独消除检查与使用之间的竞态。

```text
风险：resolved = canonicalize(root + input); checkInsideRoot(resolved); open(resolved)
     // 路径检查有意义，但当攻击者能改父目录/链接时，之后的 open 仍可能指向别处
修复形状：使用目标平台能落实根目录/链接限制的目录句柄相对操作，
          在取得的句柄上验证类型与权限，并用同一句柄执行后续读写
```

不同平台的符号链接、挂载和文件 API 契约不同，不能把一个 flag 当跨平台通用方案。归档还要检查每个条目、链接、解压后总量及最终落地范围，不只检查压缩包的文件名。

**反证**：父目录不受攻击者影响、链接策略由操作系统安全落实或路径来自受信固定映射，实际竞态前提可能不成立。**验证**：上级/绝对/编码路径、相近前缀目录、链接替换与归档条目；在受控临时根验证，无需读取真实敏感文件。区分 CWE-22 与链接/TOCTOU 根因。

## 输入放大与资源预算

从外部可控的输入量沿链估算：压缩比、嵌套深度、循环次数、查询行数、并行任务、排队与重试。只有“读取完成后检查长度”，不能保护读取/解压阶段；只有线程上限，不能保护积压队列。

按放大位置设预算：原始输入、解压后输出、解析深度/项数、每主体并发、队列、总期限和下游重试。计时和取消应覆盖真实工作，不能只让客户端提前收到超时而后台无界继续。阈值来自业务与运行容量，不能凭空规定固定数值。

**反证**：入口、生产者和最大对象大小已有共同可证明上界；同一策略不需要在每个内层重复实现。**验证**：针对本次新增放大环节测试临界、超限、慢依赖和取消；确认拒绝及时、资源被释放、正常负载仍可用。对应 CWE-400/770。

## 其余风险的判断字典

| 审查主题 | 必须完成的推导 | 修复后应成立的事实与验证 |
|---|---|---|
| 服务端请求 / CWE-918 | 证明输入影响**实际连接**的协议/地址/端口；追 DNS、重定向、重试、代理和出口 | 每个连接都受目的地策略约束；在隔离网络测受控跳转与解析变化。只“先解析一次再普通请求”仍可能失效，详见 Web |
| 内存安全 / CWE-787/125/416/190 | 从长度/指针到分配、复制、使用、回收，分别证明运算不溢出、访问范围、初始化、别名与存活期 | 用稳定输入副本和正确所有权/同步维护事实；边界、分配失败、并发释放和 sanitizer/Miri 按具体假设验证，详见 Kernel/Rust/AOSP |
| 反序列化与字段绑定 / CWE-502/915 | 分别查输入能否选择实例化类型/执行路径，以及能否赋值用例之外字段；普通 JSON 不自动等于执行代码 | 类型/字段能力由边界约束；真实解码后敏感字段不改变、未允许类型不被构造。mass assignment 按 CWE-915，不全归 CWE-502 |
| 敏感数据 / CWE-200/798/327 | 追秘密从输入到日志、错误、缓存、包、备份与网络，区分加密数据和可取得的密钥/nonce | 最小保留、合适平台密钥与成熟协议；检查发布产物、失败日志、备份恢复和密钥失效。凭据暴露后仅删源码不撤销能力 |

## 依赖漏洞的判断与处置

先识别审查目标：业务运行时、构建环境、测试/部署工具也可以是攻击面，不能用“dev dependency”一概排除。

1. 从实际解析结果/锁文件/构建清单定位生态、坐标、版本、feature、target 和使用位置；版本字符串、包名或未解析的声明不足以说明交付内容。
2. 核对维护者公告的引入/修复范围和前提，再检查供应商回移代码。工具链/std/native 库不能只靠应用锁文件审计。
3. 区分结论：**已确认含受影响组件**、**该部署中已证实可触发**、**当前配置未发现可达路径**、**代码修复已核实**。这些不同事实可同时写明，不把“尚无利用证明”写成安全，也不编造可利用链。
4. 修复选择受项目支持且包含补丁的版本/回移；公告中的历史最低修复版不是当前升级目标。暂缓升级时说明缓解覆盖哪些入口、残余风险及解除条件。
5. 重新核对最终产物、依赖和配置，运行与漏洞根因相关的负向用例及受影响业务正向用例。代码改了但尚未发布，只能说代码侧完成。

报告保留公告 ID 与版本证据作为佐证，而非用一长串 CVE 代替结论。需要量化时给 CVSS 版本、向量与环境假设，Review 的 P0–P3 不直接换算分数。

## 修复闭环：从单点补丁找同源错误

安全缺陷确认后，提取失败事实，如“复用对象未初始化能力标志”“对外部标志赋予内部信任”“先转交所有权再执行可失败操作”。搜索同类创建/复用/入口，而非只搜索一条攻击字符串。对修复逐项检查：

- 入口被拒绝或能力被收窄，合法操作仍成立。
- 错误、取消、回调和不同构建配置没有绕过修复。
- 回归用例在旧行为下能失败，在修复后能通过；尚未执行的验证明确标出。
- 暴露的凭据/数据和已发生的入侵按用户授权的响应范围另行处理；源码修复不自动完成撤销与恢复。

来源和分类边界见 [规范溯源](../sources/standards.md)；六个历史漏洞的原始公告与补丁仅归档在对应领域的 sources 文件，运行规则已提炼到本地。
