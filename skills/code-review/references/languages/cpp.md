# C++：资源对象、移动与借用失效

先确认 C++ 标准版本和库契约；`string_view` 从 C++17 起、`span` 从 C++20 起可用。这里检查语言与标准库语义，平台线程、内核锁和框架对象模型转相应运行场景，通用失败原子性沿用公共规范。

## 把释放责任交给已构造的资源对象

遇到 `new/delete` 或其他获取/释放配对，检查获取成功后、交给管理对象前是否可能抛异常。已完整构造的局部资源对象会在正常离开作用域与异常展开时析构；失败构造中，已构造成员可清理，但不能指望尚未构造完成的对象自身析构函数执行。

```cpp
auto item = new Item;
prepare(); // 抛异常时，下面的 delete 不执行
delete item;
// 所有权确属当前作用域时：auto item = std::make_unique<Item>();
```

**确认条件**：可达异常/早退跨过裸资源的释放，或默认复制使两个对象释放同一资源。**反证**：裸指针只是借用，或明确转交给会接管的所有者；不机械要求每个参数改成智能指针。检查自定义资源类的复制/移动/析构是否与唯一或共享所有权一致，并覆盖获取后下一步失败的路径。

## 移动操作后的源值由类型契约决定

`std::move` 只是允许选择移动操作的转换，本身不搬运资源，也不保证一定发生移动。标准库对象被移动后通常处于有效但值未指定的状态；不能假定仍保留原内容，也不能统一假定为空。自定义类型则查其移动实现与约定。

```cpp
std::vector<int> source{7};
auto target = std::move(source);
int first = source[0]; // 未重新证明 source 非空，索引前提不成立
```

**确认条件**：后续代码依赖未经保证的内容/大小，或自定义移动使源对象析构时重复释放。**反证**：只执行无额外前提的析构、重新赋值或查询；具体类型明确保证移动后的状态，且后续操作满足前提。检查移动后使用的实际操作，不能把所有 moved-from 使用一律报告。

## 视图与迭代器依赖底层存储的有效期

遇到 `string_view`、`span`、引用、指针或迭代器跨语句保存，检查底层对象的销毁与具体容器的失效规则。视图不拥有数据；复制视图不延长临时字符串的生存期。`vector` 重分配使全部元素引用/迭代器失效，不重分配时插入点及之后也可能失效。

```cpp
std::string_view name = std::string("ready"); // 分号后底层临时对象销毁
std::vector<int> values{7};
auto it = values.begin();
values.insert(values.begin(), 9);
int old = *it; // 即使 capacity 足够，旧 begin 也已失效
```

**确认条件**：销毁或相应失效操作发生后仍使用借用。**反证**：底层对象覆盖全部使用期，且操作按该容器规则保留此借用；`reserve` 只排除相应容量内的重分配，不能普遍排除插入/擦除失效。修复可延迟取得借用、重新定位元素或按契约持有独立值，不强制复制全部数据。

## 析构和 noexcept 不能吞掉失败契约

遇到析构调用可能抛异常的关闭/提交操作，检查异常能否逃出析构，以及析构发生时是否正在展开另一个异常。异常逃出不抛异常的函数会调用 `std::terminate`；在异常展开中析构再向外抛异常也会终止。加上 `noexcept` 不会把调用变成成功。

```cpp
~Writer() noexcept { flush(); } // 若 flush 可抛，失败会终止进程
// 需要向调用者报告写入结果时，提供显式 finish()，析构负责不抛异常的清理。
```

**确认条件**：可达失败会越过声明的异常边界，或必须报告的保存失败只能从析构暴露。**反证**：被调用操作保证不抛，或内部已执行符合契约的恢复/失败处理；不要求给每个本已不抛的析构机械补修饰符。验证显式完成失败及展开中的清理，保留原始失败信息。
