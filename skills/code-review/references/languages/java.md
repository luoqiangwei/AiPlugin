# Java 语言与标准库审查

本模块补充 Java 语言、对象契约和 JDK 基础库的精确语义；先采用项目实际的 Java 版本。以下判断跨应用、服务和系统工具成立，框架生命周期另按运行场景审查。

## 相等关系必须进入真正的覆盖方法

**进入条件**：改动值对象、继承层次、集合 key，或新增 `equals` / `hashCode`。

`equals(User)` 只是重载；经 `Object` 或集合调用仍可能执行引用相等。确认签名是 `equals(Object)`，用 `@Override` 让编译器验证。相等关系须满足自反、对称、传递，与 `null` 比较为假；相等对象必须有相同 hash，hash 冲突本身不是错误。

```java
// 风险：本类调用看似按 id 相等，HashSet 却仍按 Object.equals 判断。
boolean equals(User other) { return id.equals(other.id); }
// 修复：覆盖 equals(Object)，同步实现 hashCode，并验证跨静态类型调用。
```

追踪 key 在集合存储期间能否修改相等字段；JDK 不保证这种变更后的 Map 行为，不能把“当前 JVM 偶尔还能查到”作为正确性证据。可改用稳定身份值，或先移除再修改并重新插入。只改与相等无关的备注字段是反证，不要求整个对象不可变。

**验证**：两个独立但相等实例的集合查找、基类与子类双向比较、存储期实际修改路径；不要只测 `x.equals(x)`。

## 擦除后的检查不证明元素类型

**进入条件**：跨遗留接口、反射、反序列化的 cast，或泛型 varargs。

`List<String>` 的类型参数会被擦除；`instanceof List<?>` 只证明外层容器，向 `List<String>` 的 unchecked cast 不会逐个检查元素。沿实际写入点定位污染，而不是只修之后编译器插入强转的读取行。

```java
Object raw = List.of(42);
List<String> names = (List<String>) raw; // unchecked；这里通常不会失败
String first = names.get(0);            // 到实际读元素时失败
```

边界若承诺字符串列表，应逐项验证后构造受控容器；仅换成 `List.class.cast(raw)` 仍未证明元素。泛型 varargs 的数组若经 `Object[]` 别名被写入另一种列表，同样能污染；`@SafeVarargs` 不能修复该路径。

**关键反证**：私有容器的全部写入均受同一类型约束、可变别名不逃逸时，局部 cast 可以有完整证明；unchecked 告警不自动形成 finding。

## 自动关闭有明确的注册与异常顺序

**进入条件**：新增 `AutoCloseable`、手写 `finally` 或多资源初始化。

try-with-resources 从左到右初始化，按相反顺序关闭已成功初始化的非空资源；后一个初始化失败也会关闭前面的资源。业务与关闭同时抛异常时，先前异常保留为主异常，关闭异常成为 suppressed exception。

```java
// 风险：finally 的 return 把业务异常和原有返回值一并覆盖。
try { return compute(); } finally { return fallback; }
// 修复：清理放在不会改写控制流的 finally，或使用 try-with-resources。
```

把两次资源获取都先放在 `try` 外，第二次失败时第一份资源没有自动清理保障。获取函数内部若先分配、再失败且未返回，该内部资源也未注册到调用方的资源声明；由获取函数自己清理。

**验证**：业务失败、后续初始化失败、每个 close 失败；检查关闭顺序、剩余资源和主异常及 `getSuppressed()`。资源已明确转移所有权给返回对象时，不能机械要求本层关闭。

## final 的初始化保证有边界

**进入条件**：懒加载、跨线程缓存、构造器注册监听器或启动线程。

先找构造完成前 `this` 是否进入共享位置，包括注册回调和调用可能被覆盖的方法。正确构造且没有提前逃逸时，读线程取得对象后享有 final 字段及其所引用对象的构造期状态保证；这不覆盖普通字段或构造后的修改。

风险：`final List<T> items` 被当作线程安全可变集合，或普通共享引用被当作非 final 字段的发布屏障。修复：让发布写入与读取通过同一锁、volatile 或实际库契约形成 happens-before，并另行约束后续修改；volatile 引用本身不使集合操作原子化。

**关键反证**：完整构造、无后续变化且满足 final 字段语义的不可变对象，不能仅因引用通过普通字段传递就断言其 final 状态可见性失败；仍应分别判断引用的及时可见性与其他状态。

**验证**：写出发布前写入、发布动作、读取动作和后续写入之间的关系；确定性检查逃逸入口。压力测试未复现不能推翻内存模型允许的错误执行。

出处与适用边界见 [Java 一手依据](../sources/java.md)。
