# BPF 代码审查

用于 eBPF 程序及其 Map、事件消费者和加载代码。目标是从变更中找出可达的性能退化、策略错误、数据错误和资源泄漏；Android 平台差异再读对应专题。verifier 通过不证明业务正确，也不证明高频路径的成本可接受。

## 从变更进入具体检查

先确认 program/attach type、真实 hook、调用频率和这段代码必须完成的工作，再沿受影响路径展开。只有修改构建、加载或兼容能力时，才补齐对应交付链证据；不为审查一处计数逻辑先写整套架构说明。

| 看到的变化 | 优先寻找的缺陷 |
|---|---|
| 新增 helper、封装调用、循环、调试或事件 | 每次触发多做了什么，是否被 PPS/事件率和循环次数放大 |
| 包读取、pull、copy、改头、checksum、redirect | 是否处理了不需要的数据，是否破坏边界、指针或 fallback |
| lookup/update、计数、规则布局或配置切换 | 重复工作、共享写竞争、跨端字节协议和旧状态解释 |
| section、Android.bp、loader、pin、attach 或版本门控 | 产物是否实际生效、失败是否可见、旧实例与资源是否被正确接管 |

## helper 是否让高频路径做了无用工作

**进入条件**：逐包、每 syscall、调度/tracepoint 路径新增 helper，或把原来低频的操作移进循环与公共入口。先展开宏和封装，沿可达分支数调用；不能只数变更行里的 `bpf_*`。

写出 `触发率 × 命中分支比例 × 循环次数 × 每轮调用/处理字节数`，比较改动前后。多级 hook 或程序链分别计入，不能将线路包数直接当作某程序的调用次数。同吞吐下小包可能有更高 PPS；verifier 能证明循环有界，仍可能每包执行几百次查表。不要给所有 helper 规定统一数量上限或固定耗时。

| 代码信号 | Review 要证明什么 | 修复及限制 |
|---|---|---|
| 同一次执行对同一 key 反复 lookup，或无条件 update 未变化的值 | 沿实际路径数次数；结果是否真的需要刷新，update 是否承担发布/建项/同步语义 | 在契约允许时复用本次结果或去掉无效写；共享配置、Map 删除/替换和 helper 引起的失效先排除，不跨触发缓存裸指针，也不把复用当原子快照 |
| 在规则、字节或嵌套循环内调用 helper | 循环上界和最坏合法输入；参数、查表结果是否循环不变，攻击者能否放大次数 | 只外提真正不变且可安全复用的工作；按查找语义改索引/算法，不能随意截短规则、漏校验或漏记账 |
| feature、协议、UID 或采样条件在昂贵调用之后才判断 | 不需要该功能的流量是否也查表、读取包或构造事件；这些调用是否有必需副作用 | 将独立且廉价的筛选前移；不跳过授权、必需统计和安全审计，不把“未采样”当作免于业务处理 |
| 每包拉取整段数据、反复小块 copy、按全包计算 hash/checksum | 实际只需哪些字节；长度与次数是否受大包、分片和非线性 skb 放大 | 按目标 hook 支持选择最小必要读取；需要修改/连续访问时仍要保证 writable、边界与 checksum，不凭“少调用”换错误 |
| 每次触发都 printk、采集 stack、复制大事件或 perf/ringbuf 输出 | 诊断是否启用、谁消费、记录大小/频率、满缓冲行为；关闭输出后是否仍在准备数据 | 在构造前门控，按诊断契约采样/聚合，提供有界丢失计数；可靠审计另保留明确交付要求 |
| miss 后频繁 insert/delete、LRU churn 或所有 CPU 更新同一计数 | 热点 key、容量、命中率和 writer；成本来自 helper 次数、分配/驱逐还是 cacheline 争用 | 按状态语义改容量、建项协议或分片；per-CPU 会改变汇总、一致性及内存成本，不能自动替换策略/配额 Map |

**可确认的反例**：产品的逐包路径为每条规则重复读取同一份本次调用内固定的配置；上限 64 条，实际仅扫描结束后才判断功能关闭。即使关闭功能，每包仍做 64 次 lookup。若关闭后契约无需这段处理且调用无必要副作用，可静态确认无效工作；修复是先读取/判断一次，再仅对启用流量执行必需扫描。不能无测量进一步声称“增加了多少毫秒、功耗或丢包”。

**排除误报**：不同 key 的独立查找、必须刷新的并发状态、miss 后建项并重新取得 value、真正需要的包写入、受控低频诊断以及已有正确门控，不能仅凭 helper 多就报告缺陷。查表调用可能被目标实现优化，最终成本还要结合 Map type、JIT/生成代码和实测；也不能反过来用“可能被优化”否定已证明的可达冗余。

**验证**：用同一目标内核、对象构建与业务配置比较前后；覆盖功能关闭/开启、常见/最坏规则数、hit/miss、小包高 PPS、大包/GSO、多 CPU 和慢消费者。分别断言结果不变、冗余路径调用数/工作量下降，以及吞吐、CPU/包、延迟、丢包、输出丢失等受影响指标；Android 功耗另在相同负载与设备条件下测量。

程序运行统计只能辅助定位：仅在目标支持且环境允许时使用，记录统计开销；对同一程序对象、可比的统计开关/窗口且 `Δrun_cnt > 0`，`Δrun_time_ns/Δrun_cnt` 是所观测程序的平均值，不是 helper 归因、尾延迟或全链路 CPU。追具体成本需同条件 profiling/对照，不用一张平均值截图声称找到 helper 瓶颈。

## skb helper 是否引入不必要的拉取、复制或指针失效

**进入条件**：新增 `bpf_skb_pull_data`、`bpf_skb_load_bytes/store_bytes`、adjust、checksum 或直接包写入。

- 只读小头却无条件 `pull_data(ctx->len)`，要追到为何需要整个 skb 连续且可写；全包拉取可能在 cloned/nonlinear 路径引入复制或线性化，不能只测普通线性包。
- `pull_data(0)` 按目标实现可能确保当前线性区可写，不等于空操作，也不等于全包线性化。直接写包的生成 prologue 也可能承担这一工作；不能不看真实写入与目标实现就删除。
- `skb->len` 包含非线性数据，不能代替 `data_end` 的直接访问边界。按所需范围选择读取/pull，检查失败；不能为减 helper 改成越界直接读。
- 按目标 helper 契约判断包指针/证明是否失效：允许改变底层存储或使已有包指针证明失效时，检查返回后重取 `data/data_end`、重建指针并复核边界，不能因某次走了未移动的快路径省略。不是所有 helper 都要重做全部解析。
- 读固定 IPv4 头后按固定长度找 TCP，要用 options、分片和截短输入检查；改写还核对 checksum、offload 元数据及后续栈看到的表示。

**确认/修复**：指出合法包在哪一分支额外处理了多少不需要的范围，或哪个访问/重写失去保证；以最小必要读取、正确写前条件和明确失败策略修复。**反证**：真实后续访问需要该范围或 writable 处理、分支已正确门控时不能删。**验证**：同时测线性/非线性、共享 skb、边界包与 fallback 的行为和成本。

## 为了省调用有没有改坏 Map 与业务语义

**进入条件**：合并 lookup/update、改计数、换 per-CPU/LRU、增加缓存、调整结构或批量读清。

- 列出 BPF、其他 CPU、用户态和旧程序全部 writer。共享 value 的 `packets++` 会丢更新；单字段可用目标支持的原子操作。`lookup → 修改 → update` 不是事务，hash 元素替换的原子性不能保护前面的读改写。
- 单字段原子不提供多字段快照；per-CPU 也不是全局原子快照。需要一致配置/配额时先还原发布、读取和回收协议，再考虑目标支持的 lock/版本方案；不能只给部分参与者加锁。
- 用户态 per-CPU 缓冲区按所用 ABI 的 possible CPUs、slot 对齐和 value size 分配；不要按在线 CPU 数量猜大小。吞吐收益须与汇总成本和内存增加一起判断。
- key/value/事件逐字段核对宽度、端序、padding 和单位；初始化全部可读取/导出的字节，优先共享定义和尺寸/偏移断言。`packed` 不是通用修复。
- 旧 pin 的 type、size、flags、容量一致仍可能字段语义不同；同尺寸重排、计数重置、复用 UID/ifindex 或默认值变化，要给出错误归属/策略的具体样本。按契约保留布局或版本化迁移，不能为省兼容判断直接清空状态。
- Map 满、lookup miss、LRU 驱逐、并发建项/删除与遍历分别推演。缓存可丢不表示授权/限额表可随意驱逐；新增 helper 重试也要有进展和上界。

**验证**：让两个 CPU 同读 N 再写 N+1，断言两个调用应增加 2；覆盖并发发布/读取、满表和旧格式非零样本。只测顺序计数、空 Map 新启动或新结构自身 round-trip 抓不到上述问题。

## 错误路径、返回值和事件是否完整

- 每条 return 对照本 program/attach type：XDP、TC direct-action、socket filter、cgroup 等含义不同。列解析失败、未命中、helper 失败和缺配置的决策；统计缺失不自动丢包，安全策略缺失也不能默认放行。
- tail call 成功不返回；失败继续下一条指令。以缺项、替换窗口和目标不兼容检查 fallback，不能把末尾 PASS 当通用兜底。
- ringbuf reserve 失败、perf 输出错误及慢消费者按契约处理；普通 reserve 成功后所有路径 submit/discard，初始化完整记录；dynptr 按自己的失败收尾契约。拥有引用的 helper 配对 release，借用引用不乱释放。
- 关闭日志/采样不能隐藏必要的加载、attach、降级和恢复结果；输出不含无必要的 payload、UID/PID、地址、命令行或残留字节。诊断本身也受上面的成本检查。

**验证**：故障注入要断言具体行动码、Map/包副作用、引用与事件状态；不能仅断言“无崩溃”或“verifier 接受”。

## 只在改到部署与生命周期时追完整链路

追 `交付 .o/metadata → Map 创建或复用 → load → pin/attach → 消费者 → 替换/清理`。取本次受影响边界的证据，不从源码存在推断产物被交付，也不把 load/pin 成功当实际 attach。

- 新 helper、指令、Map/程序类型、kfunc 或循环特性：查目标 commit/config、回移和 program-type 限制；头文件或版本字符串不证明支持，不沿用历史禁循环/固定上限。verifier 拒绝时定位对应访问边界、未初始化、引用或复杂度，不能用强转压过证明义务。
- 采用 libbpf/CO-RE 时才核对 BTF、重定位和同一对象的 skeleton；CO-RE 不补齐缺失能力，也不证明字段业务含义稳定。Android 不默认走该路径。
- attach 前后初始化窗口、部分失败、替换空窗和旧程序并存：写出哪一刻策略可用，谁回滚本次资源、谁保留旧实例。
- FD、pin 和 attachment/link 的责任分开：关 FD 不保证停止，unlink 不保证没有别的引用；按实际 API 管理 detach/close。共享 Map 不能随单个消费者退出删除；pin 跨进程退出存活，不跨整机重启持久保存。

**验证**：目标 load/verifier 与真实 attach 分层取证，覆盖必需/可选失败、重复启动、停止、更新与回滚。未触及的部署细节不作为本次 Review 的额外门禁。

## 把结论交给修复者

finding 写 `具体变更 → 可达输入/频率/时序 → 无效工作或错误状态 → 影响 → 最小修复 → 区分用例`。已证明的冗余、已测量的退化和待验证的成本分别写清；没有证据时不虚构耗时、功耗、丢包或漏洞等级。

优先静态推导、已有测试和隔离的对照验证。目标支持时可用 `BPF_PROG_TEST_RUN/BPF_PROG_RUN` 检查返回和状态，但它会执行程序并修改引用的 Maps；使用独立对象/Maps，不用线上 `prog_fd` 或生产 pin。live-frame 另有真实网络副作用，普通返回码也不证明真实链路 drop/redirect 或性能。

真实加载/attach 与设备压力测试在获准环境执行；记录实际环境、结果和未覆盖层次。目标树 selftests 只选受影响机制；缺设备、跳过或旧分支不支持均不能写成通过。
