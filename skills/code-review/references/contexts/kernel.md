# Linux 内核与驱动

适用 Linux 内核、驱动及 Android common/vendor kernel。先记录目标 commit、vendor 回移、架构/位宽、`.config`、PREEMPT/RT、执行上下文和子系统；以下伪代码只表达证明义务，具体 API 采用受审树的契约。

eBPF 程序、helper、Map 或挂载点变化时，按 [场景索引](../index.json) 的 `kernel.checks.bpf` 读取 BPF 专题。BPF 的允许操作由程序类型、目标内核和验证器决定，不能机械套用普通内核 C 代码的分配、锁和指针 API；审查内核 BPF 实现本身时再使用本文件相应机制。

## 选择检查路径

| 代码变化 | 进入的检查 |
|---|---|
| 对象查找、引用、删除、RCU | 引用与生命周期 / RCU 发布与回收：证明取得引用之前内存就有效 |
| 用户输入、分配、解析、结构体拷出 | 用户内存复制 / 尺寸与初始化：证明检查和使用的是同一份数据与大小 |
| IRQ/work/timer、probe/remove、锁变更 | 锁与执行上下文 / 停止与清理：证明停止返回后已无访问者或新任务 |
| 对象池、状态位、新构造路径、回移修复 | 尺寸与初始化 / 补丁回移与同源错误：证明每次创建都重新建立全部状态 |

不要以“有锁”“用了 refcount”“sanitizer 没报告”结束分析。写出谁能与谁交错、交错后哪条不变式被破坏。

## 引用获取、删除与回收

**需要保持的事实**：查找得到指针时，其内存尚未释放；从保护区退出后继续使用，必须已经拥有独立引用；最后一个拥有引用释放时，对象已从可成功取得新引用的入口摘除。RCU 旧读者仍可能看见已摘除对象，但不能复活归零的引用。

执行顺序：

1. 找出初始引用、容器持有的引用、每次返回给调用者的引用及对应 `put`，分别标记“借用”和“拥有”。
2. 将查找与删除并排阅读，找出“拿到裸指针 → 增加引用”之间保护内存的机制。增加计数本身不能复活已释放内存。
3. 找出最终释放及所有错误路径。容器摘除、回调注销、引用归零是不同事件，不能混成一次 `free`。
4. 若是 RCU，分别证明发布可见性、写者互斥、grace period 与最终回收。读侧临界区结束后，裸指针不自动继续有效。

```c
/* 风险：如果 registry_get 只返回借用指针，remove 可在两行之间释放 p。 */
p = registry_get(id);
refcount_inc(&p->refs);

/* 一种完整的锁保护方案：容器在锁内始终持有一个引用。 */
spin_lock(&registry_lock);
p = registry_find_locked(id);
if (p)
    refcount_inc(&p->refs);  /* 容器引用保证此时计数非零且内存有效。 */
spin_unlock(&registry_lock);
/* 使用 p 后 put(p)。删除方在同一锁内摘除，解锁后放掉容器引用。 */
```

RCU 方案不能直接照搬上述加引用语句：若删除后计数可归零，读者通常需要在仍受 RCU 保护的内存上尝试获取非零引用，并处理失败；实际原语、重试及延迟释放由数据结构的完整协议决定。仅把 `refcount_inc` 改成 `refcount_inc_not_zero`，而没有保证计数所在内存仍有效，仍不成立。

**排除误报**：若调用者已经持有引用，或查找 API 明确在内部安全取得引用，上述“查找后使用”不构成缺陷；应检查 API 实现与每条返回路径，而非按函数名猜测。

**有区分力的验证**：令查找暂停在取得指针/引用的边界，同时执行删除与最后一次 `put`；正确结果是返回有效拥有引用或查找失败。再覆盖失败 unwind、重复删除、模块退出与回调未完成。KASAN/RCU 调试辅助发现交错，不能代替这套所有权证明。

## 长度、分配与用户内存复制

**需要保持的事实**：分配字节数足以容纳被访问的数据；长度运算没有先溢出或截断；数据验证后不会再次从可变用户内存取回未经验证的字段；拷出不泄漏未初始化字节。

执行顺序：

1. 从 `__user` 入口追踪每个 count/offset/size 的类型、位宽和符号转换，写出最终访问区间。
2. 在乘加之前检查溢出，按业务限制数量；“结果小于最大值”不能补救已经溢出的运算。
3. 先复制必要的头部，再根据内核副本计算大小；复制数组后，对内核数组逐项校验。`access_ok` 不能证明内容、范围内所有页或后续操作一定成功。
4. 检查 `copy_from_user/copy_to_user` 的非零返回：它表示仍有字节未复制，不是负 errno。短复制后的对象不能当作完整请求继续执行。

```c
/* 风险：乘法先溢出；检查 count 后又从用户地址读 count。 */
bytes = user_count * sizeof(*items);
items = kmalloc(bytes, GFP_KERNEL);
process(items, get_user_count_again());

/* 修复形状：固定头部只取一次，尺寸检查先于分配。 */
if (copy_from_user(&h, uh, sizeof(h)))
    return -EFAULT;
if (!h.count || h.count > MAX_ITEMS ||
    check_mul_overflow((size_t)h.count, sizeof(*items), &bytes))
    return -EINVAL;
items = kvmalloc(bytes, GFP_KERNEL);
if (!items)
    return -ENOMEM;
if (copy_from_user(items, uitems, bytes)) {
    kvfree(items);
    return -EFAULT;
}
/* 校验 items 的字段，再使用；所有退出路径释放 items。 */
```

**排除误报**：count 来源已经是更窄的受限类型时，先算可达最大值；不用重复要求不存在的溢出检查。检查上层是否已复制并校验，且下层是否仍使用同一副本。复制期间用户可变不意味着必须取得原子快照，但完成后必须验证实际拿到的内容。

**有区分力的验证**：正常数量、零/上限/上限加一、乘法边界、32 位截断、跨不可访问页的短复制、用户并发修改原始头部；失败时无业务副作用。结构体拷出还检查 padding、保留字段及错误分支是否初始化。

## 停止生产者与释放资源

**需要保持的事实**：资源释放后，IRQ、work、timer、DMA 完成和外部查找均不能再次访问它；等待回调退出时，不能持有回调自身需要的锁。

先画资源状态：`分配 → 初始化 → 注册 → 对外公开 → 停止接收 → 排空/同步 → 释放`。为每个 probe 失败点画出逆向清理路径，标清 devm 与手动管理的责任。

```text
风险时序：remove 释放 dev → 已排队 work 开始 → work 使用 dev
风险修复：remove 持 mutex → cancel_work_sync → work 等同一 mutex → 死锁

有效修复顺序（依子系统调整）：
  在生产者共同遵守的同步下设置 stopping，并撤销对外入口
  阻止或同步 IRQ/timer/回调等任务生产者，保证不能再 enqueue
  放开回调所需的锁，再同步取消/排空已有 work
  确认外部引用和回调已退出，最后释放资源
```

设置一个 `stopping` 标志本身不够：核对每个 enqueue 路径如何读取它，以及检查与排队之间能否再次和 remove 交错。`cancel_work_sync` 也不是永久禁用后续排队的机制。

锁变更还要沿调用链检查执行上下文：是否可睡眠、是否会被同 CPU 中断重入、锁顺序是否形成环。PREEMPT_RT 改变部分锁语义；不能用“spinlock”这个名字推导全部抢占和 IRQ 行为。

**排除误报**：资源由更长生命周期的父对象持有、回调自身持引用，或子系统注销 API 已保证排空时，按该契约判断，不重复要求第二套机制。

**有区分力的验证**：在每个注册步骤注入失败；让 remove 与 IRQ/work 同时发生；重复 bind/unbind；检查既无释放后访问，也无永不返回的清理。按假设使用 lockdep、KASAN、kmemleak 和目标硬件测试。

## 复用对象的初始化

**需要保持的事实**：构造函数返回时，决定所有权、权限或数据解释的每个字段，都反映本次对象类型，而非上一个使用者。

沿所有构造/复制/池复用路径列出字段写入矩阵，特别检查 `flags`、长度、owner、操作表、页/FD 引用和错误标志。只检查第一次分配是否清零会漏掉后续复用。

```c
/* 风险：另一个创建路径只改 page/len，继承旧的 capability flags。 */
buf = pool_take();
buf->page = page;
buf->len = len;

/* 修复形状：每条构造路径按类型建立完整状态，而非事后碰到错误再补。 */
init_buffer_for_readonly_page(buf, page, len); /* 明确设置 flags/owner/ops 等。 */
```

**判定与反证**：先找到残留字段的实际消费者，证明旧值会改变敏感行为；如果池归还/取出协议已经保证完整重置，应把它作为反证。不能因为未使用 `kzalloc` 就直接报未初始化漏洞。

**验证**：使用具有不同状态的对象连续复用，覆盖每条创建路径和错误回收路径；断言新对象的能力、长度和引用独立于旧对象。Dirty Pipe 提炼出的就是这条检查方法：追查所有创建路径中的状态初始化，而非只记住一个 CVE 和修复版本。

## 剩余检查与结论要求

| 审查主题 | 可执行判定规则 |
|---|---|
| 发布与内存顺序 | 对发布/消费分别标记写入、观察和回收顺序；证明配对同步关系。`READ_ONCE` 不等于完整的 acquire，CPU 内存排序也不能替代所需的设备/DMA 协议。 |
| 用户 ABI 兼容 | 对已发布 uAPI 比较字段偏移、尺寸、保留位、32 位 compat、错误码与旧二进制行为；内部重构不应泄漏为 ABI 改变。 |
| 配置与条件构建 | 将每个新增配置下的调用和实现配对：内建/模块、功能禁用 stub、链接依赖与错误处理均要成立；只测一个 defconfig 不能覆盖受支持组合。 |
| 运行开销 | 把外部可控输入换成最大合法值，估算循环、分配、栈和锁持有成本；有明确调用频率或测量基线才判性能退化。 |
| 补丁回移与同源错误 | 回移修复检查实际代码、前置补丁与同类创建路径；版本字符串、缺少主线 SHA 或扫描命中都不能单独证明补丁缺失。 |

每条 finding 必须给出具体时序或边界输入、违反的不变式、可达影响，以及与安全实现的差异。checkpatch/sparse 用于缩小检查范围；KUnit 验内部逻辑，kselftest 验用户可见接口，选择目标树支持的工具和测试。
