# 浏览器与 HTTP 服务

先确定代码运行在浏览器、SSR、边缘还是后端，记录认证方式、代理/CDN、缓存、数据库和实际锁定版本。以下规则可直接用于审查；示例是机制示意，函数名不代表现成框架 API。Spring 实现再组合 Spring 模块。

只读取本次运行位置相关的部分：浏览器变更关注 DOM、跨站、会话使用、页面缓存、交互、性能与可访问性；服务端入口关注对象授权、HTTP 缓存、输入、持久化和请求资源。只有服务端代取 URL 才进入 SSRF 检查，只有页面输出进入对应解析上下文才检查 XSS。SSR 等同时跨越两侧时再组合；只给前端代码不能证明后端已经正确授权。

## 检查入口字典

| 审查主题 | 进入条件 | 要证明的不变式 |
|---|---|---|
| 对象与租户授权、缓存隔离 | 对象 ID、租户、权限或缓存变化 | 返回的数据与副作用都属于当前主体被允许的集合；缓存命中也不越过边界 |
| 输出上下文与脚本注入 | 不可信文本进入页面、URL、模板或 DOM | 数据不能改变接收点的语法结构或启用未经允许的执行能力 |
| 服务端请求目的地 | 服务代取 URL、Webhook、预览、导入 | 每次实际连接和重定向只到允许目的地，且资源消耗有界 |
| 并发副作用与幂等 | 支付、库存、额度、任务与请求重试 | 并发、重复和故障恢复后，业务不变式及副作用次数仍符合契约 |
| 会话与令牌、跨站请求防护、跨域响应访问 | 身份、跨站或凭证配置 | 请求身份可信；自动附带凭证不能被跨站滥用；读取与操作授权分别成立 |
| 解释器与文件输入、输入与资源预算 | 查询、命令、路径、解析与上传 | 输入不能扩展操作语义，解析前后均有适当资源上界 |
| 页面性能、可访问性 | 页面加载或交互变化 | 在目标设备预算内，用户能感知并完成操作，键盘与辅助技术不被阻断 |

## 对象授权与缓存隔离

**沿链检查**：把主体、租户、对象 ID 分别追到可信来源，再追到查询/更新与每层缓存。特别检查列表、批量导出、附件、后台任务及“已登录所以可读”的分支。

```text
风险：authenticate(); return cache.get(id) ?? repository.findById(id)
     // 登录成立；对象归属未证明；命中可能完全跳过数据层检查
修复示意：subject = verifiedIdentity()
          object = repository.findVisibleTo(subject, id)
          if absent: reject
          return authorizedView(object, subject)
```

- **确认条件**：合法低权限主体选择授权集合外的对象，沿真实入口读/改数据。控制器没检查时继续查服务、查询过滤、数据库行策略和网关，不在第一层下结论。
- **缓存再检查**：应用内缓存不会因 HTTP `Vary` 自动隔离。键应覆盖决定内容的安全分区；权限会改变时，命中前重新授权或使失效策略与权限变化一致。共享缓存中的用户响应按契约使用 `private`/`no-store`，并核实 CDN 规则。
- **安全情形**：内容本来公开；用户确实共享同一授权视图；服务或数据库已对每次读取完整授权。此时不机械地把 userId 加入所有键。
- **最小修复**：在可信操作边界绑定主体与对象，不只隐藏前端按钮；优先停止错误共享或补足隔离，不默认重构授权架构。
- **回归**：A 先填缓存，B 请求同 URL/ID；切换租户、角色或撤销权限后再次命中；批量混入未授权 ID。拒绝路径不泄漏对象内容，合法访问仍成功。

**中间件绕过的根因模型**：外部请求头、路径和 Cookie 不因名称像“内部标志”就可信。遇到“内部子请求跳过鉴权”，查标记由谁生成、入口是否剥离伪造值、直连源站/备用路由是否旁路，以及敏感操作的最终授权保证。匹配一个历史攻击头不等于封闭所有旁路。

## 输出上下文与脚本注入

1. 找最终接收点，反向追内容来源；数据库、翻译、URL 参数和第三方接口不会天然可信。
2. 区分文本、HTML、属性、URL、CSS、JavaScript；确认框架转义是否被逃生接口、拼接或后续 DOM 修改取消。
3. 让防护匹配**最终上下文**：HTML 转义不等于 JavaScript 编码，URL 编码不等于协议限制。

```javascript
// 风险：名字被重新解释为 HTML
title.innerHTML = profile.displayName;
// 纯文本需求：避开 HTML 解释器
title.textContent = profile.displayName;
// URL 是另一边界；textContent 不能替代协议与目标策略
const target = new URL(input, location.origin);
if (target.protocol !== 'https:' || !allowedOrigin(target.origin)) reject();
link.href = target.href;
```

- **确认条件**：不可信内容能改变目标语法或执行语义，没有有效编码/净化/策略阻断；只看到 `innerHTML` 不够，先排除静态或适当净化的内容。
- **富文本需求**：用维护中的净化器及允许策略；净化后不再拼回原始字段。检查允许标签、属性、协议及组件二次处理。
- **安全情形**：纯文本绑定、固定模板加安全变量、对当前上下文有效的转义。CSP 是附加保护，不能独自证明危险拼接安全。
- **回归**：在真实接收点输入引号、尖括号、协议和嵌套标记等无害数据，断言 DOM 结构/链接能力未意外扩展。覆盖存储回显、客户端导航与净化后组件渲染，并保留合法富文本。

## 服务端请求与实际连接目的地

**进入条件**：用户能影响服务端请求的 URL、host、端口、代理或跳转目标。业务能固定目标时不必接受任意 URL。

```text
风险：if allowed(parse(url).host): http.get(url, followRedirects=true)
     // 再次解析、DNS、重定向可能把连接送到别处
修复示意：限制 scheme/host/port → 对解析结果执行目的地策略
          → 由能落实该策略的传输层连接 → 每次跳转重复同样过程
          → 限制连接/读取/解压后大小及总耗时
```

- **追踪**：解析/规范化→DNS 全部候选地址→客户端选择→代理/网格→重定向→重试。核对 IPv4/IPv6、回环、私网、链路本地与业务允许范围，不用字符串前缀判断。
- **确认条件**：外部主体能让服务连接禁止目标或执行有害内部请求。接受外部 URL 不足以确认，先查客户端策略、出口与实际可达能力。
- **最小修复**：关闭无必要的自动跳转，固定/精确允许目标；动态目标由连接层落实校验结果，或由可信出站代理/出口约束实际目的地。“先解析检查，再普通请求”仍可能二次解析。保持 TLS 主机名校验，不以 IP 连接为由关闭证书验证。
- **安全情形**：目标由可信配置决定，或所有实际连接被可验证的出口约束；不再要求业务重复实现不完整解析器。
- **回归**：受控服务跳转至禁止地址、DNS 混合地址/变化、重试、超大/压缩响应；确认没有禁止连接且正常抓取仍成功。在隔离环境验证，不探测真实生产元数据或管理接口。

## 重复请求与业务副作用

```text
风险：if not exists(key): charge(); saveSuccess(key)
     // 两并发都通过；扣款后崩溃还会重复扣款
修复示意：用 (tenant, operation, key) 唯一约束认领并记录 payloadHash
          → 同 key 同载荷复用状态/结果；异载荷拒绝
          → 外部副作用使用对方稳定的幂等键，保存可恢复结果
          → 故障后查询/对账恢复，不盲目重新创建副作用
```

- **追踪**：写余额/库存/唯一订单等不变式→标出检查与修改的原子边界→枚举崩溃与重试点→区分本地提交、外部成功、响应送达三个状态。
- **确认条件**：给出造成重复、超卖、丢更新的具体交错/故障序列。串行重试成功不证明并发安全；有事务也不代表隔离与约束足够。
- **最小修复**：本地用条件更新、版本、锁或约束；本地事务不能回滚外部扣款。按需求用可靠投递、幂等消费及恢复，outbox 不会让外部操作天然 exactly-once。
- **安全情形**：重复本来符合契约；数据库已维护不变式；仅显示顺序问题可用客户端请求序号，不必引入服务端幂等记录。
- **回归**：并发同请求、同 key 异载荷、外部成功后本地提交前中断、响应丢失、乱序显示。断言业务状态与真实副作用次数，不只数方法调用。

## 其余规则：从线索到可确认结论

| 审查主题 | 执行判断 | 反证与验证 |
|---|---|---|
| 会话与令牌 | 追签名/算法、issuer、audience、期限及撤销契约，登录/提权防固定，秘密不进 URL/包/日志 | 不强求所有 token 在线撤销；按产品承诺测错误受众、签名、过期、登出和权限变化 |
| 跨站请求防护 | 先判浏览器自动携带凭证，再查 token/Origin 与豁免；JSON、REST、“无状态”不能直接豁免 | 仅显式携带且攻击站点不可得的令牌可能不满足经典前提；用真实跨站请求证明，不把 CORS 当写保护 |
| 跨域响应访问 | 带凭证并反射任意 Origin 时证明攻击站点能读敏感响应；精确查协议/host/port、`null`、预检 | 公共无凭证资源可用 `*`；能发请求不等于能读响应，也不能替代服务端授权 |
| 解释器与文件输入 | 逐段追到 SQL/命令/模板/路径；参数只绑定数据，动态语法用固定映射；文件再查链接与竞态 | 当前解释器有效参数化是反证；测试结构改变、跨根路径与上传落地能力 |
| 输入与资源预算 | 分别查原始/解压后大小、深度、页长、并发、总时间、重试放大与断连清理 | 预算依据流量/业务，不凭个人阈值；测临界值、取消、满队列和慢上游 |
| 页面性能 | 找变更引入的长任务、瀑布、包体、布局代价，用同设备网络和预算比较 | 单次实验室结果不证明现场体验，TBT 不等于 INP；无实质影响的微优化列建议 |
| 可访问性 | 键盘完成主流程；查语义/名称/错误关联、弹窗开关焦点，缩放后仍可操作 | 自动扫描不是完整证明；指出具体不可达操作，不笼统报告“缺少无障碍” |
