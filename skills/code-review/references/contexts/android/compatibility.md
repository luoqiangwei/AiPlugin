# Android 兼容性与测试证据

本文件用于平台、OEM、系统组件或接口变更的兼容性 Review；普通 App 只选受影响的 API、targetSdk 与设备回归，不要求全量 CTS。
兼容性审查先证明发布契约与实际行为一致；运行 CTS 是取得证据的一种方式，两者不能等同。
固定目标 Android 分支、manifest revisions、product/ABI、首发或升级设备、user 构建、测试套件版本及 system/vendor 组合。
CDD 与行为要求选择该版本及设备类别；网页“最新”、本机 SDK 或另一产品通过记录不能代替目标基线。

## 把变更映射到契约和真实测试

**风险**：以“内部重构”跳过兼容性，或只按模块名选测试，漏掉调用者可观察的异常、权限和数据格式变化。

1. 从差异写出 `调用者/设备条件 → 原行为 → 新行为 → 对应 SDK/CDD/稳定接口要求`，包含配置和删除项。
2. 用真实 API、权限常量、异常类、feature 字符串、AIDL 包/实例名在目标 checkout 中 `rg` 搜实现与断言。
3. 先读变更目录及祖先的 `TEST_MAPPING`，展开 imports、group、options、file_patterns；再查测试源码和 `Android.bp/Android.mk`。
4. 核对模块确实构建到所用 suite、filter 确实选到方法、preparer 是否改变权限/用户/feature，不能仅凭测试名称认定覆盖。
5. 对每个契约记录 `已有断言 → 未覆盖分支 → 需补的最小回归`；TEST_MAPPING 缺项说明调度缺口，不能推出没有测试。
6. 目标从本分支构建定义和测试类取得；Atest 可按实际模块、类、方法或路径定位，不编造通用目标名。

测试变更同样审查：删 feature、改 expected/assume/skip、扩大权限或提高超时，须有目标产品 CDD/API 契约与可测原因支持。
若只是避开失败输入、隐藏必需能力、授予测试主体额外能力或掩盖性能退化，则“绿”不构成修复；修复应落到真实行为与有效断言。
产品确有允许差异、测试假设错误或合理设备时间预算时保留合法差异，但说明条件并回归原失败场景，不能一律禁止调整测试。

示例命令只在目标 AOSP 环境采用；路径和变量先替换为已定位的真实值，选项以本分支 `atest --help` 为准：

```sh
rg -n 'TEST_MAPPING|test_suites|LOCAL_COMPATIBILITY_SUITE' "$changed_dir"
rg -n --fixed-strings "$api_or_feature" cts frameworks hardware test
atest --test-mapping "$changed_dir" --dry-run
atest "$verified_test_identifier" --dry-run
```

dry-run 只检查选择/解析证据，不证明测试已执行或用例足够；父目录测试也不必然包含同级或子目录测试。
**反证**：仅私有实现变动且调用边界、配置和持久化输出可证明等价，不因没有新增 CTS 就报兼容缺陷。
**回归**：正向复现受支持的旧调用方式；负向使用改变的输入/身份条件，确认对应断言在错误实现上会失败。

## API、权限、异常和 targetSdk 切换

**风险**：签名未变但新增权限、把异常改为空结果、改变默认值，或所有调用者误入只应针对新 targetSdk 的分支。

- 对 SDK/System API 对照本分支 API 文本、文档、实现及 CTS；签名检查不能证明运行语义、线程或错误契约。
- 逐项区分无权限、AppOps 拒绝、对象不存在、非法参数和后端失败；拒绝须符合既定异常/返回约定且无副作用。
- 查入口与深层分支使用的调用者 targetSdk、compat change 和 fallback；不把服务自身 targetSdk 当客户端条件。
- 安全修复也要核对批准的兼容方案；不能为保持旧行为保留越权，也不能无依据扩大为所有旧 App 的行为破坏。
- 修复选择保持发布契约、正确放置版本门控或实现明确降级；不能通过捕获所有异常制造“兼容成功”。

**反证**：目标版本明确允许的新行为或仅影响新 targetSdk 的正确门控，不因与旧版本不同直接报错。
兼容框架开关可隔离原因，覆盖范围、可切换性受版本/App debuggable/构建限制；关闭开关不能作为发布修复。
**正向回归**：同设备运行边界下/边界上的 targetSdk 客户端，验证授权成功及旧行为保留；再用实际发布 targetSdk 运行默认配置。
**负向回归**：每组测拒绝权限、撤权、非法参数和不存在对象；重置 compat override 后复测，防止人为关闭变化掩盖问题。

## Parcelable 与跨版本消费者

**风险**：本机 round-trip 通过，但字段默认值、null、空集合、枚举和旧读端不兼容；测试只看对象相等，漏掉后续字段错位。

先确定是进程内临时对象、手写 Parcel，还是承诺版本稳定的结构化 AIDL；不能把所有 Parcelable 当可持久化、跨任意版本协议。
在已有编解码审查上补测试矩阵：旧写/新读、新写/旧读，按实际支持的升级关系选组合，末尾哨兵校验消费位置。
结构化 AIDL 的编译兼容检查之外，检查新增字段的业务默认值、未知枚举处理、新方法失败/降级及 FD 所有权。
**修复/判定**：保持旧布局或按受支持机制演进；只有实际跨版本承诺被破坏才报兼容缺陷，格式可解析不证明业务安全。
**反证**：无稳定承诺且两端原子升级的内部对象，不机械要求任意旧端读取；仍审查不可信 Parcel 和失败清理。
**正向回归**：合法 null/空/非空、旧端省略字段、旧接口调用成功；**负向回归**：截断、超大长度、未知值拒绝或按契约降级。

## 多用户、设备能力和 feature 声明

**风险**：只在主用户或有硬件设备上通过；缓存按包名/appId 合并不同用户，或删除 feature 声明让测试被跳过。

- 从 API 查询和产品 permissions XML 追到实际硬件/软件实现；声明、feature 版本、返回能力与 CDD 条件必须一致。
- 查测试中的 assume/feature gate、用户创建条件和跳过原因；零失败但零执行不能证明相应功能兼容。
- 用户维度覆盖权限、安装状态、设置、回调和存储；同包不同用户不能共享仅应属于单用户的状态。
- 修复实际能力与声明的失配，或按该类设备允许的契约返回不支持；不能虚报能力，也不能为规避测试隐去必需能力。

**反证**：可选硬件确实不存在且声明/行为符合该产品 CDD，相关测试合理跳过；多用户和 profile 要按真实支持类型判断。
**正向回归**：能力存在时执行真实操作，主/次用户各自得到本用户结果；**负向回归**：无能力/无权限/跨用户请求按契约拒绝。
再测用户切换、停止/删除重建和后台回调，断言旧用户数据不进入新用户；合理的显式跨 profile 共享按授权契约验证。

## 稳定 HAL、ABI 与测试套件边界

**风险**：当前 system/vendor 一起构建通过，却改坏旧 vendor、实例发现、VINTF、接口默认值或 native ABI。

1. 找稳定边界：AIDL 冻结 API/版本/依赖、HIDL 版本、VINTF manifest/matrix、NDK/native 导出符号及实际消费者。
2. 检查冻结内容未被改写，新增能力有版本协商/降级，实例名与服务注册一致；ABI 变化按真实承诺和工具输出判断。
3. 从本分支 HAL/VINTF 测试构建定义取得目标，读断言与实例枚举；只验证能找到服务不足以证明每个接口语义。
4. 正向用受支持的旧 vendor/新 system 和实际发布组合运行；负向测缺失可选实例、未知方法/字段、服务死亡和不支持能力。

| 证据 | 适合回答的问题 | 不能据此推出 |
|---|---|---|
| CTS 与必要的 CTS Verifier | 面向 App 的平台 API/行为及需人工观察的设备能力 | 所有 CDD 条款、安全边界和厂商扩展都已覆盖 |
| VTS 与对应 HAL/VINTF 检查 | vendor/HAL/kernel 和分区接口契约 | App 行为与所有端到端功能均正确 |
| CTS-on-GSI | 确有 Treble/vendor 独立兼容需求时，用参考 system 验证 vendor 接口 | OEM 完整镜像功能、任意版本组合均兼容 |

**反证**：产品从未承诺的分区/ABI 组合不能凭失败直接判回归；须先证明其在目标升级/发布矩阵内。
CTS-on-GSI 涉及专用设备和镜像准备，仅在该边界必要且环境获准时安排；Review 不自动刷机、解锁或改策略。

## 交付证据与剩余缺口

记录每项实际命令、checkout/套件版本、设备 fingerprint、ABI、构建、用户/权限条件、执行/跳过数量及原始结果位置。
区分构建通过、测试运行通过、未执行、环境失败、基线已有失败；retry 通过要保留首次失败并解释是否为受影响路径。
单次 CTS 绿不能替代静态推导、负向回归和未覆盖 CDD 条款，也不等于没有安全缺陷。
无设备/厂商镜像时仍可完成契约比较、真实测试定位和缺口判定，但必须标注运行行为“未验证”，不写“兼容性通过”。
