# Android 与 AOSP 日志

用于新增、删除、改级别或改变频率的日志，以及异常处理、服务启停、Binder/HAL 恢复和队列拒绝路径。目标是让必要事件在交付环境可诊断，同时去掉误导、重复、泄密和代价失控的输出；不要求每个函数或每次失败都打印。

先读 Android 应用或 AOSP 场景；阻塞因果按 ANR、Watchdog 专题继续推导，本文件只检查日志引入的开销和证据缺口。

## 先还原发布时的日志链路

- 固定设备/API、平台 revision、App build variant、product 的 user/userdebug/eng、日志封装和后端；列出关键事件由谁记录、在哪里读取、保留多久。
- 普通 App 使用公开 `Log` 或项目封装；此基线 `Log` 写 main，`Slog` 写 system，后者是平台/模块 API，不能作为普通 SDK App 的替换方案。native 同样核对实际 buffer、宏定义和目标构建参数。
- `BuildConfig.DEBUG` 查实际导入模块生成的值及构建配置；它是 App/模块构建开关，不是设备 userdebug 判断。`Build.IS_DEBUGGABLE` 是平台隐藏字段，本基线来自 `ro.debuggable`，也不代表某 APK 可调试；普通 App 不照搬平台 API。
- `Log.isLoggable(TAG, level)` 是运行时 tag/级别条件，不等于 `BuildConfig.DEBUG`，也不提供脱敏或权限保护。调试开关为 false、调用已被 R8 删除时，改属性不能恢复代码；静态缓存的开关还要核对属性变更何时生效。
- 分别检查编译/R8 裁剪、代码条件、liblog 属性/进程最低级别、采集权限和 logcat 显示过滤。`log.tag.*`、`persist.log.tag.*` 与产品配置须按实机取证；user 构建不会自动删除所有调试调用，WARN/ERROR 也不是永远可读或持久保存的保证。
- release APK 核对合并规则和实际产物，平台核对 Soong/native 编译参数与镜像配置；不从源码的一条 `Log.i` 或开发机可见性推断交付可见性。

## 级别由真实状态与故障影响决定

| 级别或入口 | 审查判断 | 常见不合理用法 |
|---|---|---|
| VERBOSE / DEBUG | 开发细节、单次输入/回调轨迹；受有效开关控制且费用有界 | 每帧常开；唯一的注册失败证据仅在 DEBUG；为了让线上看到而一律升级 ERROR |
| INFO | 按诊断契约保留的正常操作摘要或重要状态迁移，如服务真正 ready、停止完成、恢复成功 | 把“开始尝试”写成成功；无诊断价值的高频成功输出造成噪声或超预算；release 已裁掉却依赖它定位恢复 |
| WARN | 需要关注但可处理的降级、重试异常或资源压力，说明后续动作；预算内普通重试可用受控细节或汇总 | 正常空结果、取消或协议内拒绝一律 WARN；无限重试每轮同样堆栈 |
| ERROR | 已发生的操作/服务契约失败，说明受影响能力、原因及处理结果 | 预期探测失败、用户输入无效、可选对象不存在被记成系统故障；仅打印“failed” |
| wtf / fatal | 不应发生的不变式破坏或明确的终止策略，继续读实际处理链 | 用更醒目级别记录断网、HAL 暂不可用、正常权限拒绝或其他可恢复错误 |

异常类型不能独立决定级别；同一种 `RemoteException` 在启动前探测、已就绪服务死亡、关机阶段可能有不同含义。级别调整须保留实际失败语义和恢复策略，不能只为清净日志降低真实故障。

`Log.wtf` 会进入 terrible-failure 处理，不是普通 `Log.e`。官方 API 描述可能包含报告或终止；实读 android16-release 的实现先按 ERROR 输出，再调用处理器，RuntimeInit 根据上游返回决定是否退出。`Slog.wtf` 还传 system 标志，其契约与普通 App 不同；报告、异步处理和进程处置须核对目标调用链，不能断言所有 wtf 都立即崩溃或都安全返回。

native 的 `LOG_ALWAYS_FATAL[_IF]` 调用断言入口，默认 aborter 会终止进程；`LOG_FATAL[_IF]`、`ALOG_ASSERT` 是否存在于产物受 `LOG_NDEBUG` 等影响。本基线没有 `ALOG_FATAL` 宏，遇到该名称先展开项目封装；单纯传入 `ANDROID_LOG_FATAL` 优先级也不能替代对 abort 调用的确认。不要把断言、状态修改或必要清理藏在可能被裁掉的日志参数中。

## 关键路径必须留下足够诊断证据

沿 `请求/启动 → 校验/注册 → 就绪 → 失败/降级 → 重试 → 恢复/停止` 列必要事件，关注此前可见的能力何时消失、为什么、是否恢复：

- 系统服务启动和停止、发布/回调注册失败、部分初始化失败，区分 attempted、ready、failed、stopped；启动日志不能充当完成证据。
- HAL/daemon 异常、Binder death、断连、重连耗尽与恢复，记录稳定组件/实例标识、原因码、状态/代次、重试或降级结果；按需求保留耗时、累计次数，避免完整请求体。
- 权限/策略拒绝、满队列丢弃或提交失败，确保能区分正常拒绝、异常压力和工作丢失。高频事件可按原因与时间窗聚合，保留计数、首次/末次或恢复点；有安全审计责任时仍保留所需主体/操作/结果证据，且数据最小化。
- tag 稳定地定位组件，消息表达操作与结果；跨层用不含秘密、作用域有限的关联标识。堆栈在负责处理/报告的一层记录，必要时使用 Throwable 参数保留 cause；单独 `e.getMessage()` 不能提供调用栈，异常消息和堆栈本身也需检查敏感内容。
- 同一异常在 DAO、repository、Binder、调用者逐层“打印后抛出”时，沿传播链选择最有上下文的责任层；其他层只在补充独立状态或改变失败语义时记录。不能删去唯一包含根因、受影响实例或恢复结果的记录。

只有证明某个重要可达故障在交付配置下失去必要证据、且现有渠道没有覆盖，才确认“漏日志”。仅缺少本地 `Log.e` 不足以成立；调用者已得到明确错误并有适当记录，或协议内高频空结果无需逐次输出，是有效反证。

| 既有渠道 | 能提供的证据 | 不能直接推出的结论 |
|---|---|---|
| logcat | 带 tag/级别/时间的文本和相关 buffer 事件 | 循环缓冲不是永久审计库，未采到不证明没发生 |
| EventLog | 面向系统集成的有 tag/schema 的诊断事件 | 不能让普通 App 任意定义平台事件，也不自动包含文本根因 |
| statsd | 已定义 atom、推送/拉取与已配置收集的指标 | 一个总计数不一定定位单次实例、拒绝原因和恢复顺序 |
| Perfetto | 已启用数据源/埋点覆盖窗口内的时序、调度与调用关联 | trace 未启用不能补日志；`android.log` 的构建和过滤限制另核对 |

这些渠道各有用途，不能凭“有 statsd/Perfetto”互相替代。反证必须指出真实写入点、字段、发布配置、采集/保留范围及故障时可获得的结果；重复已有充分证据也没有必要。

## 高频和临界路径的代价要算到调用前

**触发**：主线程、Binder 入口、持锁区、Monitor、循环、每帧或高频 callback 增加字符串、对象 dump、堆栈或同步日志后端。

即使输出被过滤，Java/Kotlin 参数里的拼接、插值、`toString()`、序列化、遍历和方法调用仍可能先执行；`ALOGD` 等也须展开宏判断，不能把 liblog 后端过滤当惰性求值。日志表达式中的锁、Binder、I/O、异常和状态修改同样属于业务路径。

```java
// 风险：每帧构造全量状态；DEBUG 输出被过滤也可能执行 dumpState()。
Log.d(TAG, "frame=" + frame + " state=" + dumpState());

// 普通 App 的调试示意：开关先判断，只输出已取得的轻量标量。
if (BuildConfig.DEBUG && Log.isLoggable(TAG, Log.DEBUG)) {
    Log.d(TAG, "frame=" + frame + " pending=" + pendingCount);
}
```

**反证**：调用已被产物裁剪、实证惰性封装未求值，或低频且有界的标量输出可排除对应开销；仅写了 DEBUG 或“平常很快”不能排除。示例的双重开关也不能作为关键线上证据的唯一入口。

**修复**：去掉无诊断价值的逐帧/逐元素输出，使用状态变化、限速/采样或有界聚合；聚合器须线程安全、键空间和队列有上限。锁内只取必要标量/受控快照，锁外格式化与输出；不为日志在 Monitor、主线程或持锁路径做重型 dump、同步磁盘/网络 I/O，也不无界异步排队转移风险。

**验证**：关闭调试与启用详细日志分别压测，观察回调/帧耗时、分配、锁持有时间、Binder 完成率及每秒条数/字节；用能记录求值次数的受控对象证明关闭路径不执行昂贵表达式。日志风暴不能淹没真实故障或拖出 ANR/Watchdog；后者按对应专题验证等待链。

## 断连与恢复的完整推演

```text
触发：已 ready 的 HAL 死亡，重连持续失败，随后恢复。
风险：唯一异常被 Build.IS_DEBUGGABLE 包住；user 上静默降级。
      另一版本每次 retry 在三层打印 ERROR 堆栈，却没有恢复事件。
反证：已有发布可采集的事件含实例、原因、代次和恢复结果，且覆盖本路径；
      无需再复制一套文本。仅有“重连总次数”不能证明这些字段齐全。
修复：在状态拥有者记录一次断连及原因；重试按有界窗口汇总失败次数，
      明确耗尽/降级，恢复提交成功后记录恢复与耗时；保留必要根因。
      记录点在发布配置可见、开销有限、内容脱敏，放在安全的锁外位置。
验证：对真实交付 APK/镜像关闭调试，注入 death、持续失败、耗尽和恢复；
      核对状态顺序、字段、级别和计数，检查日志风暴与旧代回调不会误报恢复。
```

## 发布、隐私与交付检查

不原样输出认证 token、凭据、密钥、账户内容、完整 Intent/Bundle、带秘密的 URI 查询参数或完整业务 payload；结构化参数、异常和对象 `toString()` 也可能泄漏。诊断所需的非敏感业务字段，以及经批准的主体/设备关联标识，按允许字段、作用域、访问和保留策略记录，不因字段属于业务就一律删除。检查标识是否可跨会话追踪；hash 或截断不自动等于安全脱敏。

在真实 release/user 配置下分别核对必要故障可见、调试细节关闭、R8/属性未误删证据、敏感哨兵未进入日志/报告。安全拒绝聚合须仍满足实际审计责任；不以“普通第三方读不到全机 logcat”证明可以记录秘密，也不为验证放宽权限或开启永久详细日志。

报告写明具体触发路径、证据缺失/污染/开销的后果、现有覆盖反证、最小改动与实测结果；纯 tag 命名偏好不单独报缺陷。来源、分支和 API 差异复核见 [规则溯源](../../sources/android-logging.md)。
